# Задание 5


На основе анализа Swagger API сервиса `client-info`,  спроектирована эквивалентная GraphQL-схема (schema.graphql), которая:

* Позволяет клиентам **гибко выбирать необходимые данные**, а не запрашивать все подряд.
* **Снижает количество запросов** к API за счет объединения данных в одном GraphQL-запросе.
* Улучшает **производительность** за счет получения только нужных полей.



**Как это решает проблему?**

* В REST `client-info` приходилось делать **3 отдельных запроса** для получения данных о клиенте (`/clients/{id}`, `/clients/{id}/documents`, `/clients/{id}/relatives`).
* В GraphQL теперь можно запросить **все данные одним запросом**, указав только нужные поля.

Пример GraphQL-запроса:

```
query {
  client(id: "123") {
    name
    age
    documents {
      type
      number
    }
    relatives {
      name
      relationType
    }
  }
}

```

**Результат:**

* Больше **не нужно делать лишние HTTP-запросы**.
* Клиент сам **выбирает, какие данные ему нужны**.
* Оптимизация **нагрузки на `client-info`** за счет уменьшения RPS.
